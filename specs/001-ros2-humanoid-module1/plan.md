## 1. Technical Context

### Architecture Sketch:
A complete workflow from Spec-Kit Plus → Claude Code → Docusaurus → GitHub Pages. This workflow illustrates how:
- Prompts (from Spec-Kit Plus) generate initial chapter content.
- Claude Code refines and expands these chapters.
- Docusaurus structures the content into a navigable book.
- GitHub Pages publishes the final book for access.

### Section Structure:
The book will follow a defined layout:
- Introduction
- Concepts
- Tutorials
- Advanced Sections
- Appendices
Docusaurus will be configured for sidebar generation and a logical folder hierarchy to support this structure.

### Research Approach (Research-Concurrent Writing):
Information will be collected concurrently from official documentation (Docusaurus, GitHub Pages, Spec-Kit Plus, Claude Code) while drafting chapters. Examples and verified commands will be integrated directly.

### Workflow Definitions:
- Each chapter is expanded using Spec-Kit Plus.
- Edited and refined in Claude Code.
- Committed to GitHub.
- Deployed via GitHub Pages.

### Key Decisions Needing Documentation:
- **Theme choice**: Classic vs Custom Docusaurus Theme.
- **Deployment choice**: GitHub Pages using `gh-pages` branch vs GitHub Actions automation.
- **Folder structure**: `docs/` only or `/docs` + `/blog`.
- **Sidebar mode**: autogenerated vs manual `sidebars.js` config.
- **Markdown format**: MDX vs pure Markdown.
- **Spec-Kit Plus usage**: define which prompts generate chapters, code blocks, architecture diagrams, and examples.

### Testing Strategy:
- **Build tests**: `npm run build` must pass without warnings.
- **Link tests**: no broken links using Docusaurus link checker.
- **Deployment tests**: GitHub Pages must correctly render all docs, sidebars, assets, and images.
- **Spec tests**: each Spec-Kit Plus expansion must produce structurally consistent chapters.
- **Code block tests**: all code snippets (npm, git, Docusaurus config) must run successfully.
- **Versioning tests**: verify Docusaurus versioning works if used.

## 4. Phase 1: Design & Contracts

### Data Model (`data-model.md`):

#### Entity: Book
- **Description**: The entire collection of educational content.
- **Attributes**:
    - `Title`: "Physical AI & Humanoid Robotics"
    - `Theme`: "Embodied Intelligence and AI Systems in the Physical World"
    - `Goal`: "Teach students to control humanoid robots (simulated + limited physical) using ROS 2, Gazebo, Unity, NVIDIA Isaac, and Vision-Language-Action systems."
    - `Modules`: List of Module entities.
    - `TargetAudience`: ["Students with basic Python/AI knowledge entering robotics", "Educators evaluating a robotics-heavy curriculum"]
- **Relationships**: Contains Modules.

#### Entity: Module
- **Description**: A self-contained unit of the book, covering a specific topic.
- **Attributes**:
    - `Title`: "The Robotic Nervous System (ROS 2)" for Module 1.
    - `Chapters`: List of Chapter entities.
- **Relationships**: Belongs to a Book, Contains Chapters.

#### Entity: Chapter
- **Description**: A specific section within a module, focusing on a sub-topic.
- **Attributes**:
    - `Title`: e.g., "Introduction to ROS 2 and Humanoid Control", "Nodes, Topics, Services, and Actions".
    - `Content`: Markdown/MDX text, code blocks, diagrams.
    - `Length`: 800-1500 words (constraint).
    - `Diagrams`: Mermaid or SVG format (constraint).
- **Relationships**: Belongs to a Module.

#### Entity: SpecKitPlusPrompt
- **Description**: A structured input used by Spec-Kit Plus to generate content.
- **Attributes**:
    - `Type`: e.g., "chapter-generation", "code-block", "diagram-generation".
    - `Parameters`: Specific inputs for content generation.
    - `OutputFormat`: Markdown/MDX.
- **Relationships**: Generates Chapter Content.

#### Entity: CodeBlock
- **Description**: Verified code snippets embedded within chapters.
- **Attributes**:
    - `Language`: e.g., Python, Bash.
    - `Content`: Source code.
    - `VerificationStatus`: Verified (run-tested or syntactically correct).
- **Relationships**: Belongs to a Chapter.

#### Entity: Diagram
- **Description**: Visual representations within chapters.
- **Attributes**:
    - `Format`: Mermaid or SVG.
    - `Content`: Diagram definition.
- **Relationships**: Belongs to a Chapter.

### API Contracts (`contracts/`):

#### 4.2.1. Spec-Kit Plus to Chapter Content Generation Contract
- **Endpoint/Mechanism**: Spec-Kit Plus CLI commands / prompts.
- **Input**: Structured prompts (SpecKitPlusPrompt entity).
- **Output**: Markdown/MDX content for chapters, including embedded code blocks and diagrams.
- **Error Handling**: Prompt generation failures, validation errors from Spec-Kit Plus.

#### 4.2.2. Claude Code Content Refinement Contract
- **Endpoint/Mechanism**: Claude Code API/interface.
- **Input**: Raw or partially generated chapter content (Markdown/MDX).
- **Output**: Refined, expanded, and validated chapter content.
- **Error Handling**: Hallucinations, syntax errors, non-compliance with constraints.

#### 4.2.3. Docusaurus Content Ingestion Contract
- **Endpoint/Mechanism**: Docusaurus build process.
- **Input**: `docs` directory containing Markdown/MDX files, `sidebars.js` configuration, static assets.
- **Output**: Static HTML, CSS, JS for the book website.
- **Error Handling**: Build failures (`npm run build`), broken links, asset loading issues.

#### 4.2.4. GitHub Pages Deployment Contract
- **Endpoint/Mechanism**: GitHub Actions workflow / `npm run deploy`.
- **Input**: Built Docusaurus site (static files).
- **Output**: Publicly accessible website on GitHub Pages.
- **Error Handling**: Deployment failures, incorrect rendering.

Before you begin, ensure you have the following installed:
